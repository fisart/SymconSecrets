# SEC API compatibility — native-only replacement branch

This branch preserves the original SEC module identity and instance IDs while replacing its executable implementation with the native backend adapter. Application calls never use old storage or keys, old login and master/slave synchronization remain disabled, and no fallback exists. Import old vault is separately available as a native-administrator-approved read of retained encrypted pre-switch data; Local secrets only is the browser default. The old manager does not execute, and its stored data and keys are never updated. Native APIs remain available in parallel. No live Symcon installation has been switched by preparing this branch.

A unique ready backend is detected automatically and pinned by instance and vault identity without changing the instance's selection property. If it is still recovering during module update/startup, binding retries every five seconds and API calls resume when it becomes ready. Multiple ready backends require selection by name. Local application reads are enabled by default; explicit native revocations remain effective. Writes remain frozen until approved for the native backend, with separate bulk permission. There is no mode choice or old-instance read grant. Saved old properties have no authority. `SEC_GetReplacementInfo($existingID)` reports the native-only engine and selected backend; `SECB_GetLegacyAPIStatus($backendID)` diagnoses native application access.

| Original API | Native behavior |
|---|---|
| `GetKeys(): string` | JSON string of top-level Global application names; hides internal areas and omits unavailable conflicted entries. |
| `GetSecret(string $ident): string` | Exact top-level key lookup, scalar-to-string conversion, structured JSON text, legacy empty-folder/list formatting, and empty-string failure. `__LOCAL__` returns this installation's Local application data. A slash in the identifier remains a literal key, not a nested lookup. |
| `GetExplorerFields(string $ident): array` | Nested application path lookup with `Key`/`Value` rows and legacy scalar conversions. Uses a root-relative path; the old console Explorer's transient navigation state and `EXPL_*` UI actions are not replicated. |
| `SetRecordFields(string $path, array $fields, string $scope): bool` | Same path/field normalization and scalar replacement while preserving nested folders. Native write permission and writable Global policy apply; saved old roles have no effect. Changes commit through the new encrypted journal and Global peer queue. Unrelated typed native subtrees remain unchanged. |
| `ExportLocalSecrets(): string` | Same pretty-printed `__LOCAL__` application envelope and folder markers. Native administrator credentials are deliberately excluded. |
| `ImportLocalSecrets(string $json): bool` | Replaces only Local application data; malformed inputs fail. Any `__AUTH__` input is rejected atomically, including otherwise valid Local data in the same request. |
| `EncryptAndSave(string $jsonInput): void` | Explicitly approved bulk application replacement, with the original success/error output under native write/bulk policy. Omitted Local data is cleared as in the old implementation. Native administrators, policy, pairings and keys are preserved. Internal/credential injection is rejected. Requires separate bulk permission and an unfrozen writer. |
| `IsPortalAuthenticated(): bool` | Checks the new origin-bound server-side session, actual credential, administrator, origin generation, revocation, idle/absolute expiry, and backend readiness. Anonymous/error cases return false. Does not refresh or extend the administrator session. |
| `ClearVault(): void` | Clears compatibility editor state only. The old function also only hid/cleared its editor; it did not erase the vault. |
| `CheckLocalSecretStore(): string`, `CheckDirectory(): void` | Native status diagnostics, rather than diagnostics for obsolete `system.vault`/legacy keys. |
| Legacy admin/UI APIs listed below | Their exact method signatures are present for discovery, but execution explicitly refuses and points to the native approved workflow. These are **not behavior-compatible operations**. |

Explicitly unavailable legacy operations: `SaveAuthToken`, `ShowToken`, `SaveHookPass`, `SaveSlavePass`, `GenerateToken`, `SyncSlaves`, `InitializeSlaveSecretStore`, `LoadVault`, `UpdateUI`, `RemoveAllPasskeys`, `RevokePortalSessions`, `ResetPortalLoginPageRateLimit`, `ResetPortalChallengeRateLimit`, and old `RequestAction` console Explorer actions. Master/slave shared-key transport has no safe equivalent in the peer protocol. Credential administration and throttling cannot bypass the new approval rules. `__AUTH__` and other reserved identity data are never exposed by the compatibility application view.

Thus **application interface compatibility is implemented; universal behavioral equivalence is not claimed**. Scripts using those administrative calls must use the new approved workflows before being accepted for migration. This distinction is intentional and must remain visible in migration reports.

## Authentication and failures

The preserved old hook accepts a plain local `/hook/<name>` return path and uses only the native origin-bound administrator session. Native credentials, revocation, expiry, logout and restart control access. Primary and fully approved Magic access use their own native cookies and credentials. Old sync/admin requests and external or recursive return paths refuse execution.

Data methods retain the original empty/false failure shapes. Refused reads retain a sanitized diagnostic and log at most once per minute per instance without writing PHP warnings/notices into consumer responses; a fallback `[]` is not proof of an empty vault. No old-data fallback occurs. Native writes recheck explicit approval/freeze within the encrypted transaction and use native peer sharing. All local SEC consumers share the native backend's application access settings; they are trusted local PHP callers, not separately token-scoped identities.

See [the cutover and rollback instructions](../.migration/NATIVE_ONLY_REPLACEMENT.md) and [the local preflight script](../.migration/Preflight_Native_Replacement.php). Switching this branch replaces every old module instance together. Backups, value comparison and live consumer acceptance must precede operational use. Rollback requires the saved code and configuration; native writes are never copied into inactive old files.
