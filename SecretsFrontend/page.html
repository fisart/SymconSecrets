Operating guide

Follow step-by-step instructions for first-time setup, using secrets, connecting platforms, Magic backup access and importing an old vault.

Overview

System status shows connections and sharing progress, Magic backup access, available Global and Local secret values, conflicts, vault storage and active access grants. Open Connection status to investigate a platform. Status updates every 10 seconds while Overview is visible; background checks compare each platform’s complete Global state, normally every minute. Failed or stale checks appear under Connection status. Conflicts are shown separately from synchronization. Refresh status checks immediately. If an update fails, the figures are marked as out of date. Magic access and local Connect service status are checked separately; an active configuration does not prove an outage test succeeded.

First-time setup: steps 1–5

The Setup assistant creates this platform’s encrypted vault and first administrator. It disappears from navigation after setup. Add later passkeys in Key enrollment; use Recover administrator access on the sign-in page or in Access & keys if access is lost.

  1. In the Secrets Frontend console, enter your trusted HTTPS address if requested and click Step 1: Open setup.
  2. In the browser, click Prepare first passkey and follow your device’s prompt.
  3. Keep the browser open. In the console, click Step 3: Refresh approval requests, compare all four identifier groups, and click the matching Step 3: Approve. Return to the browser; it checks automatically.
  4. In the browser, review the suggested backend, storage and optional connections. Click Review setup plan. Confirm storage persistence or permissions if asked.
  5. Check the summary, click Set up and sign in, and confirm with your passkey.

If the result is uncertain after you confirm, use Resolve accepted setup in the console; do not begin a second setup.

Using Secrets

Select a location, then browse the folders on the left and their contents on the right. Single-click to select. Double-click a folder to open it. Choose Show folder values to see values beside their names, then use 📋 (Copy value) to copy a value or click the value to edit or delete it. If clipboard access is unavailable, the value is selected for your browser’s Copy command. When creating or changing a secret, use Generate password to fill the value with a random password. The default length is 24 characters; adjust Length or Include symbols if the service requires it. The password stays hidden until you use the existing eye. Select Save and approve the change to store it. Use the eye next to the entry field to show or hide what you type. If a hardware-key policy protects viewing, confirm with that key. Use Hide values to clear visible secrets. Values also hide after 30 seconds; copied values remain on your clipboard. Use New folder and New secret to create items, and Back or Up one level to navigate. Select or open a folder, then use the pencil (Rename folder) or bin (Delete), including for an empty folder. The confirmation shows the exact target; deleting a folder also deletes its contents. On touch screens, select a folder and choose Open folder. Lists and other data types can be managed in the advanced editor.

Shared installation: steps 1–6

Start on one platform. The wizard handles the other platform through an approval popup; you do not copy invitations or navigate its administration menus.

  1. 1 · Prepare: complete initial setup once on both platforms. Open Connections on the initiating platform, choose Other platform and select Connect from here. Allow the popup and sign in there if asked.
  2. 2 · Invitation: confirm creation when prompted. The invitation transfers directly to the selected popup. Previous pending connections require exact removal approvals before replacement.
  3. 3 · Request: confirm the request in the approval popup. The wizard delivers it and reports remote delivery errors here. Use Show approval popup if your browser does not bring it forward, or Retry delivery on the other platform after correcting a delivery problem.
  4. 4 · Approve: the popup closes after acknowledged delivery. The initiating wizard compares the exact vault, invitation and connection codes, then opens the final approval automatically. Confirm the displayed platform and sharing scope.
  5. 5 · Check sharing: the wizard checks both directions for this pairing and current Global revision. Remain on this page; it advances when the signed exchange succeeds. HTTPS errors remain visible and require correction.
  6. 6 · Ready: use Open Global secrets. Global is one shared vault. Both platforms can edit it; concurrent versions require Resolve conflict. Local secrets stay private. Applications need Automation access grants.

Cancel guided connection, cancelling an approval or leaving the page stops coordination. Existing requests remain listed under Your connections. The old copy/paste process remains under Advanced: manual invitation setup.

Global, Local and Conflicts

Connected platforms share one Global vault automatically. Local stays private. Open Conflicts to resolve different versions of the same secret. Other secrets remain available.

Backup access with Symcon Connect: steps 1–4

  1. Sign in at your usual address. Open Key enrollment and select 1 · Find Symcon Connect.
  2. Check the address, select 2 · Allow backup setup, and approve with your existing passkey.
  3. Select 3 · Create backup passkey. Allow the popup. There, select Create and test backup passkey and follow both passkey prompts.
  4. Return to the primary window, compare the displayed fingerprint with the popup, select 4 · Review and activate, and approve with your existing passkey.

Keep the popup open while you approve Step 4 in the primary window. It checks automatically. When Continue to sign in becomes available, select it and use your backup passkey. Save the Connect address and test a fresh sign-in. To cancel setup or remove the route, select Remove backup access / cancel setup. If the page reports that verified HTTPS transport is missing, the relay needs qualification before backup access can be used. If setup expires or Symcon restarts, repeat Step 3.

Once active, the Magic administration URL provides the same functions as your usual address, using a separate passkey and session. Existing limited access requires Approve full Magic access at the primary address or in the Symcon console; review the listed credentials, approve, then sign in again at Magic. If hardware enforcement is active, approve the upgrade at the primary address with an eligible hardware key before an outage. No vault reset or import is needed. Update all connected platforms and wait until address publication finishes before testing a primary-address outage. The console also offers Open Magic URL and Recover administrator access using Magic.

Import old vault: steps 1–4

  1. Sign in at either approved full-access address and open Import old vault. Choose an active old PasswordSafe. Under Secrets to import, Local secrets only is selected by default for joining existing platforms. It copies only the old __LOCAL__ area and leaves Global secrets unchanged. Ordinary top-level records are Global even in a Standalone vault. Select Global and Local secrets for a full import. Keep the current value is the default conflict policy. For Vault folder and Key folder, choose Keep current location or Use imported location independently.
  2. Select 2 · Review import. Check the selected scope and its conflicts, excluded internal areas, old paths, current storage folders and inactive connection proposals. Check the exact selected vault folder and key folder. Imported locations use separate subfolders beneath the old key folder. Confirm storage persistence and private permissions when selecting imported locations.
  3. Select 3 · Approve import, review the confirmation dialog and confirm with your administrator passkey. Save the downloaded pre-import encrypted backup and its separate recovery key.
  4. Check Import verified, then open Secrets. Review new vault connections to pair new systems separately. Existing applications keep using the unchanged old vault until you change their integration or switch to the native replacement branch. Finish imports and run the data comparison before that branch switch; the replacement cannot read old storage.

Existing SEC applications

Local script reads through this backend are enabled by default alongside native API calls. The backend ID and existing manager roles are detected automatically. Existing explicit access revocations remain effective. Writes stay frozen; changing write or protected-page rights requires approval. The separate old-instance replacement adapter still requires explicit approval and binding; whole-vault application replacement needs its separate permission. Approval alone does not switch applications. The prepared replacement branch keeps the old instance ID and function calls, then uses the explicitly selected new backend. Keep the old vault, keys and configuration for rollback. Legacy credential administration and master/slave synchronization require the new approved workflows. Complete backups, import verification and application tests before switching an installation.

Keep your existing system separate

Use new storage folders. The existing SecretsManager and its vault are not imported automatically.
