Configuration & backup
Configuration import / export
Hardware trust settings saved or imported in the console are staged. They become active only after this exact operation is approved. Provisioned storage, anchor trust and frontend bindings cannot be replaced through ordinary settings.
Both new modules have console export/import controls. Configuration contains paths and settings; it excludes vault contents, private keys, administrator credentials, cookies and setup codes.
Imported modules remain disabled. Check instance references, the HTTPS origin and storage locations before enabling them.
Central configuration backup
The integration package describes both new module IDs, schemas and configuration fields. The current backup module requires an explicit reviewed registry entry. Until that registration is accepted, it must not report these instances as covered.
Configuration backup is not a backup of the vault or its external keys. Secret backup/restore and automatic synchronization remain release-gated pending their implementation and fault tests.


Operating guide
Start on the separate test installation
  1. Create SecretsBackend and SecretsFrontend instances.
  2. In SecretsFrontend, paste the trusted Symcon HTTPS address and start HTML setup. Specify exact trusted proxy IPs only if your TLS deployment needs them.
  3. Copy the ten-minute setup code into this assistant.
  4. Review discovered instances and suggested private storage paths. Optional integrations and appearance are selected here.
  5. Review and save the exact configuration. The backend remains disabled; no vault or administrator is created.
  6. Continue with quorum connection, storage creation and passkey enrollment when the V2 runtime integration is available.
Boundaries
A hardware touch and PIN/biometric verification do not prove that a compromised browser displayed the right transaction. Already irrevocably authorized actions may finish after a later runtime change. Privileged host code remains outside this protection boundary.
Do not point this system at the old module’s key directory, files or database. There is no automatic migration or synchronization with the old password module.
